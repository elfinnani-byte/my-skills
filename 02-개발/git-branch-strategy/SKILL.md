# Git 브랜치 전략 도우미

1. 설계서/PRD에서 개발할 기능 단위를 추출한다. 명확하지 않으면 어떤 기능들을 브랜치로 나눌지 질문한다.
2. 각 기능에 `feature/기능명` 형식으로 이름을 붙인다. 최대한 짧게 — 축약어도 적극 활용한다 (예: `feature/education-module` 대신 `feature/edu`).
3. 기능 간 의존관계를 확인한다 (한 기능이 다른 기능의 결과물을 필요로 하는지).
4. 의존관계를 고려해 작업 순서를 정렬한다 (예: `feature/coord` → `feature/edu`).
5. 순서와 이유를 리스트로 정리해서 보여준다: [브랜치명 / 무엇을 하는지 / 왜 이 순서인지].
6. 사용자가 순서를 바꾸고 싶어 하면 이유를 듣고 반영한다.
