# 디버그 세션

1. 문제를 확인한다: 에러 메시지/스택 트레이스, 예상 동작 vs 실제 동작, 재현 방법, 최근 변경사항(배포·의존성·설정).
2. 재현 조건을 좁힌다: 언제부터 발생했는지, 어떤 범위(전체/특정 기능)에서 발생하는지 확인한다.
3. 원인을 좁힌다: 최근 커밋/배포/설정 변경을 먼저 의심하고, 관련 로그와 코드 경로를 추적한다.
4. 가설을 세우고 검증해서 근본 원인을 찾는다 (증상이 아니라 원인).
5. 수정안을 제시한다: 코드 변경 + 부작용/엣지케이스 언급.
6. 재발 방지책을 제안한다 (추가할 테스트, 넣을 가드 조건).
