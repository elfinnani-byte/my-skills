# 코드 리뷰 & 최적화

1. 리뷰 대상을 확인한다 (diff, PR, 파일 경로). 명시되지 않으면 무엇을 볼지 질문한다.
2. 보안을 점검한다: 인젝션, 인증/인가 오류, 시크릿 노출, 안전하지 않은 역직렬화.
3. 성능을 점검한다: N+1 쿼리, 불필요한 연산/리렌더링, 인덱스 누락, 알고리즘 복잡도.
4. 정확성을 점검한다: 엣지케이스, 에러 처리 누락, race condition, 타입 안정성.
5. 최적화 관점에서 개선 가능한 부분을 반드시 짚는다 (건너뛰지 않는다): 중복 코드, 더 간단한 구현, 불필요한 의존성. 개선할 게 없어 보여도 "특별한 최적화 포인트 없음"이라고 명시적으로 밝힌다.
6. 결과를 [파일 / 라인 / 문제 또는 제안 / 심각도] 표로 정리하고, 잘된 부분도 짧게 언급한다. 5번(최적화) 항목이 표에서 빠지지 않았는지 확인한다.
7. 마지막에 총평(승인 / 수정 요청 / 논의 필요)을 남긴다.
