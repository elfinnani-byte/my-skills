# Supabase 스키마 / RLS 리뷰어

1. 입력물을 확인한다. 설계서의 테이블·컬럼 설명이든 SQL DDL/마이그레이션 파일이든 받아서 테이블·컬럼·관계 목록을 정리한다. 정보가 부족하면 질문한다.
2. 테이블 설계를 검토한다: 정규화 위반, 누락된 인덱스, FK 누락/방향 오류, 부적절한 데이터 타입, NULL 허용 여부 등.
3. RLS 정책을 검토한다: 테이블별 RLS 활성화 여부, 정책 누락, 과도하게 넓은 권한(예: `USING (true)`), role/평가자 유형별 접근 범위가 의도와 맞는지.
4. 문제점마다 [테이블명 / 문제 / 왜 문제인지 / 수정 예시(SQL 또는 설계서 문구)] 형식으로 정리해서 보여준다.
5. 문제가 없는 부분은 굳이 나열하지 않는다 — 문제점 중심으로 간결하게 보고한다.
6. 사용자 확인 후 원하면 수정된 SQL이나 설계서 문구를 실제 파일에 반영한다.
