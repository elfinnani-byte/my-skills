# 테스트 전략

1. 테스트 대상(기능, API, 컴포넌트 등)과 그 안의 비즈니스 크리티컬한 부분을 확인한다.
2. 각 부분에 적합한 테스트 레벨을 정한다: 단위 테스트(로직), 통합 테스트(API/DB 연동), E2E 테스트(핵심 사용자 플로우).
3. 무엇을 테스트할지 우선순위를 정한다: 비즈니스 크리티컬 경로, 에러 처리, 엣지케이스, 보안 경계, 데이터 정합성. 사소한 getter/setter나 프레임워크 코드는 제외한다.
4. 기존 테스트 커버리지에 빠진 부분이 있으면 짚는다.
5. 계획을 [영역 / 테스트 레벨 / 커버할 케이스 / 이유] 표로 정리한다.
6. 우선순위가 높은 부분부터 예시 테스트 코드를 작성한다 (프로젝트에서 쓰는 테스트 프레임워크 기준).
